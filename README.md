# Dealer Site Audit: ИИ-агент аудита сайтов ГК «Альянс-Авто»

> Итоги тестового задания и найденное на сайтах холдинга: **[ИТОГИ.md](ИТОГИ.md)** · демо-отчёты: [reports/demo](reports/demo/)
>
> **Отчёты открываются в браузере:** [autoimport](https://velfrisko.github.io/alyans-site-audit/reports/demo/autoimport/2026-10-03_2011/report.html) · [Haval](https://velfrisko.github.io/alyans-site-audit/reports/demo/haval/2026-10-03_2022/report.html) · [Geely](https://velfrisko.github.io/alyans-site-audit/reports/demo/geely/2026-10-03_2040/report.html)

Агент проверяет сайт автодилера и выдаёт **приоритизированный список рекомендаций, которые должны увеличить число заявок**.
Работает на любом сайте холдинга и на любом другом URL. Запускается одной командой повторно (вручную, по расписанию, в CI)
и показывает, что изменилось с прошлого прогона.

```bash
python -m dealer_audit run autoimport            # сайт из реестра config/sites.yaml
python -m dealer_audit run https://любой-сайт.ru  # любой URL
python -m dealer_audit run --all                 # все 25 сайтов холдинга
```

Результат: `reports/<сайт>/<дата>/report.html` (отчёт для людей), `report.json` (для интеграций и дашбордов), `summary.md` (сводка для Telegram), скриншоты.
Примеры отчётов по реальным сайтам лежат в [`reports/demo/`](reports/demo/).

## Что проверяет

| Направление | Проверки |
|---|---|
| **Конверсия** | кликабельный телефон; телефон и кнопка заявки в первом экране на desktop и mobile (с учётом того, что кнопку может перекрывать баннер); закреплённая панель связи на мобильном; доля первого экрана, закрытая cookie-баннерами и поп-апами; мессенджеры (WhatsApp/Telegram/MAX/VK); формы: длина, маска телефона, согласие на обработку ПД, формы во всплывающих окнах (агент сам кликает по CTA); кредитный калькулятор; трейд-ин и онлайн-оценка; тест-драйв; кнопки заявки и кредит в карточке авто; онлайн-чат, Метрика, коллтрекинг |
| **Карточки авто** | поиск карточек на любой CMS (по структуре URL и содержимому); фото, цена или «по запросу», характеристики и комплектация, статус наличия, год, VIN (для б/у и импорта), кнопка заявки → полнота в %; единообразие карточек; дубли; проданные авто в каталоге; старый модельный год; **«зависшие» авто**: 45+ дней на сайте без изменения цены (по истории прогонов); пустая витрина «в наличии» |
| **Техника** | скорость на мобильном (LCP, FCP, CLS, вес, число запросов) в условиях Lighthouse: Slow 4G и CPU ×4; горизонтальный скролл, viewport, мелкие кнопки; битые внутренние ссылки (из меню, страниц и sitemap) с указанием страницы-источника; битые картинки и ресурсы; JS-исключения и ошибки консоли; HTTP→HTTPS; формы: статическая проверка, а с флагом `--test-forms` — реальная тестовая отправка |
| **SEO** | robots.txt (закрытие индексации, sitemap чужого домена, Clean-param); sitemap (пустой, ошибки, тестовые и служебные страницы); title/description (отсутствие, длина, дубли); H1; canonical; noindex; город в title/H1; schema.org (AutoDealer, Car/Offer); Open Graph; alt; **позиции в Яндексе** по целевым запросам для сайта и конкурентов (Yandex Cloud Search API) |
| **Конкуренты** | тот же сбор фактов на 2–3 местных дилерах → матрица из 15 возможностей и скорости → «у конкурентов есть, у вас нет» и «наши преимущества» |

## Как работает

```
            ┌──────────────────────────── сбор фактов (без LLM, детерминированно) ────────────────────────────┐
 URL ──▶ robots/sitemap ──▶ Chromium: главная → каталоги → карточки, кредит, трейд-ин, контакты (desktop + mobile)
            │                   detectors.js: CTA, телефоны, формы, калькуляторы, перекрытия, цены, фото, разметка
            │                   клик по CTA → поиск форм в поп-апах · замер скорости (Slow 4G, CPU×4)
            └──▶ HTTP-проверка ссылок и ресурсов (с повторами, чтобы сетевой сбой не считался ошибкой сайта)
                                   │
                    checks/*: правила → Finding (проблема, рекомендация, доказательства: URL/скриншот/значение)
                                   │                                   ▲
                    конкуренты (тот же пайплайн, облегчённый) ─────────┘
                                   │
                    LLM (опционально, сменный провайдер):
                      1) UX-разбор скриншотов глазами покупателя → дополнительные Finding (source=llm)
                      2) план действий для руководителя; каждый пункт обязан ссылаться на id находок
                                   │
                    ICE-приоритизация → HTML/JSON/MD отчёт → diff с прошлым прогоном → история карточек → Telegram
```

**Почему гибрид, а не «LLM прочитай сайт»:** факты (есть ли телефон в первом экране, сколько фото в карточке, какой LCP) надёжнее и дешевле
собирать кодом. Так результат воспроизводим, его можно сравнивать между прогонами, и он не галлюцинирует. LLM подключается там, где правила
бессильны: визуальное впечатление, понятность оффера, доверие, а также формулировка плана на языке бизнеса. Его выводы помечены отдельно и
проходят валидацию: в плане остаются только пункты со ссылками на реальные находки.

### Защита от ложных рекомендаций

Рекомендация, основанная на сбое, хуже, чем отсутствие рекомендации, поэтому агент перепроверяет себя:

* **Повторы и перепроверка.** Страницы с 5xx или ошибкой загрузки JS-чанков рендерятся повторно. Битые ссылки, картинки и ресурсы подтверждаются отдельным HTTP-запросом (3 попытки), разовый обрыв сети не попадает в отчёт.
* **Антибот.** Если сайт показал агенту капчу (Yandex SmartCaptcha и т.п.), страница исключается из анализа: иначе получились бы ложные «нет кнопки» и «нет цены». В отчёт идёт отдельная находка про капчу. Если закрыта главная, агент не делает выводов о контенте вообще и пишет, что нужен белый список IP.
* **Видимость, а не наличие в коде.** Кнопка считается «в первом экране», только если она не перекрыта cookie-баннером или поп-апом (проверка `elementFromPoint`).
* **Карточка = подтверждённая карточка.** Кандидат по URL становится карточкой, только если на странице есть цена и характеристики/год/VIN. Цены «похожих авто» не учитываются: анализируется блок от H1.
* **Слияние сигналов.** Если правило и сравнение с конкурентами нашли одно и то же, получается одна рекомендация с повышенной уверенностью, а не две.
* **Unit-тесты** на классификацию страниц, поиск карточек, правила sitemap, ICE, diff и отбрасывание «галлюцинаций» LLM.

### Приоритизация (ICE)

`score = Impact (1–5, влияние на заявки) × Ease (1–5, лёгкость) × Confidence (0–1, уверенность агента)`.
P0 ≥ 12: делать сейчас; P1 ≥ 7: в ближайший спринт; P2: бэклог. У автопроверок уверенность 0,7–0,9, у эвристик 0,5–0,6, у LLM не выше 0,7.
Веса заданы в коде правил и легко калибруются, когда появятся данные Метрики и CRM о реальной конверсии.

### Повторные запуски

Каждый прогон сохраняется в `reports/<сайт>/<дата>/`. В отчёте есть блок «Изменения с прошлого прогона»: что исправили, что появилось нового, что осталось.
Находки сравниваются по стабильному `id`. Файл `inventory.json` хранит историю карточек авто, по нему считаются «зависшие» позиции.
Индекс 0–100 по каждому направлению нужен, чтобы видеть динамику.

## Установка

```bash
pip install -r requirements.txt
python -m playwright install --with-deps chromium
cp .env.example .env   # ключи по желанию: без них агент работает, но без LLM-разбора и позиций в Яндексе
python -m dealer_audit run autoimport
```

Docker: `docker build -t dealer-audit . && docker run --env-file .env -v $PWD/reports:/app/reports dealer-audit run --all`

### LLM: сменный провайдер

| Провайдер | Переменные | Примечание |
|---|---|---|
| Anthropic Claude | `ANTHROPIC_API_KEY` | лучший разбор скриншотов (vision) |
| OpenAI / OpenRouter / DeepSeek / Ollama | `OPENAI_API_KEY`, `LLM_BASE_URL`, `LLM_MODEL` | любой OpenAI-совместимый API |
| YandexGPT | `YANDEX_LLM_API_KEY`, `YANDEX_FOLDER_ID` | данные остаются в РФ, оплата в рублях; только текстовая сводка (без vision) |
| без LLM | `--llm none` | все автопроверки, конкуренты и приоритизация работают |

Провайдер выбирается автоматически по найденному ключу или явно: `--llm anthropic|openai|yandex|none`.
Оценка стоимости LLM-части: около 15–20 тыс. токенов на сайт (4 скриншота + сводка), то есть порядка $0,05–0,15 за прогон у Claude Sonnet. Точный расход пишется в `report.json → meta.llm.usage`.

### Видимость в Яндексе

`YANDEX_SEARCH_API_KEY` и `YANDEX_FOLDER_ID` (Yandex Cloud Search API, роль `search-api.webSearch.user`). Запросы берутся из `keywords` сайта в конфиге
или генерируются по шаблону («купить {бренд} {город}» и т.п.); регион определяется по городу (Чебоксары lr=45, Йошкар-Ола lr=41).
Без ключа блок помечается «не проверено»: агент не выдумывает позиции.

## Регулярный запуск

* **GitHub Actions**: `.github/workflows/audit.yml`, каждый понедельник в 07:00 МСК и по кнопке. Отчёты сохраняются в артефакты и в ветку `reports` (история для diff), сводка уходит в Telegram.
* Конкуренты кэшируются на сутки (`reports/_competitors/`): прогон всех 25 сайтов сканирует каждого конкурента один раз.
* **cron на VPS**: `0 7 * * 1 cd /opt/dealer-audit && python -m dealer_audit run --all`.
* **Важно:** часть сайтов холдинга обрывает соединения с зарубежных IP (во время разработки это наблюдалось на knewstar, mitsubishi12, nissan-avton). Для стабильных результатов запускайте агент с сервера в РФ (self-hosted runner).

## Опции

```
python -m dealer_audit run <ключи|URL> [--all] [--max-pages 25] [--no-competitors] [--no-linkcheck]
                           [--llm anthropic|openai|yandex|none] [--test-forms] [--out reports]
python -m dealer_audit list
python -m dealer_audit summary            # сводная таблица по всем сайтам → reports/SUMMARY.md
python -m dealer_audit rebuild <папка>    # пересобрать HTML из report.json без повторного обхода
```

`--test-forms` реально отправляет тестовые заявки с именем «ТЕСТ АУДИТ (не перезванивать)» и проверяет, ушёл ли запрос и вернулся ли успех. Включайте только по согласованию с отделом продаж.

## Структура

```
dealer_audit/
  crawler.py        обход сайта, рендер desktop/mobile, поиск карточек, поп-ап формы, замер скорости
  detectors.js      извлечение фактов внутри страницы (CTA, формы, калькуляторы, перекрытия, цены, фото, разметка)
  checks/           conversion · cards · technical · seo · competitors: правила → Finding
  llm.py            провайдеры LLM, UX-разбор скриншотов, план действий с валидацией ссылок на находки
  yandex.py         позиции в Яндексе
  formtest.py       тестовая отправка форм (opt-in)
  agent.py          оркестратор; history.py — diff и история карточек; report.py + templates/ — отчёт
config/sites.yaml   реестр 25 сайтов холдинга, конкуренты, ключевые запросы
tests/              unit-тесты ядра (pytest)
```

## Ограничения и что дальше

* Агент видит сайт снаружи. Следующий шаг: подключить **Яндекс Метрику и CRM** (выгрузка заявок по страницам), чтобы калибровать Impact по реальной конверсии и считать эффект внедрённых рекомендаций.
* «Тайный покупатель»: LLM-агент с инструментами браузера проходит сценарии («хочу Haval Jolion в кредит с трейд-ином») и считает шаги до заявки.
* Мониторинг между аудитами: ежедневный лёгкий прогон (доступность, формы, пустая витрина) с алертом в Telegram.
* Сводный дашборд по всем 25 сайтам (данные уже есть в `report.json`).
* Скорость замеряется в лаборатории (headless Chromium), из-за сети цифры могут отличаться. Для полевых данных (реальные пользователи) следующим шагом подключается CrUX/PageSpeed API.
